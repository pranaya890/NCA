## What is Burp Intruder

- Burp Suite includes a built-in web fuzzer called Intruder
    
- Used for:
    
    - Web fuzzing
        
    - Enumeration
        
    - Brute-forcing
        
    - Parameter testing
        
    - Directory discovery
        
- Acts as an alternative to CLI tools such as:
    
    - ffuf
        
    - gobuster
        
    - wfuzz
        
    - dirbuster
        

# Burp Community vs Pro

## Community Edition Limitation

- Intruder speed limited to:
    

```text
1 request per second
```

## Effect

- Very slow for large fuzzing attacks
    
- Suitable only for:
    
    - Small wordlists
        
    - Short tests
        
    - Quick enumeration
        

## Burp Pro Advantages

- Unlimited request speed
    
- Faster fuzzing and brute-forcing
    
- Additional advanced features
    
- Comparable to high-speed CLI fuzzers
    

# Common Uses of Burp Intruder

- Directory fuzzing
    
- File discovery
    
- Parameter fuzzing
    
- Password brute-forcing
    
- Subdomain enumeration
    
- Authentication testing
    
- Active Directory password spraying
    

# Sending Requests to Intruder

## Steps

- Open target application in Burp browser
    
- Go to:
    
    - `Proxy > HTTP History`
        
- Right-click desired request
    
- Select:
    

```text
Send to Intruder
```

## Shortcut

```text
CTRL + I
```

## Opening Intruder

```text
CTRL + SHIFT + I
```

# Intruder Tabs

## Main Sections

- Target
    
- Positions
    
- Payloads
    
- Settings
    

# Target Tab

## Purpose

- Displays target information automatically
    
- Includes:
    
    - Host
        
    - Port
        
    - Protocol
        

# Positions Tab

## Purpose

- Defines where payloads will be inserted
    
- Uses payload position markers:
    

```text
§PAYLOAD§
```

# Example Directory Fuzzing

## Goal

- Discover hidden directories
    

## Example Request

```http
GET /DIRECTORY/ HTTP/1.1
```

## Payload Position

```http
GET /§DIRECTORY§/ HTTP/1.1
```

# Adding Payload Positions

## Methods

- Manually wrap text using:
    

```text
§
```

- Or:
    
    - Highlight text
        
    - Click:
        
        - `Add §`
            

# Important Note

- Keep empty lines at end of HTTP request
    
- Removing them may cause malformed requests
    

# Payloads Tab

## Purpose

- Defines payload wordlists
    
- Configures fuzzing behavior
    

# Main Payload Configuration Areas

- Payload Position & Type
    
- Payload Configuration
    
- Payload Processing
    
- Payload Encoding
    

# Payload Position & Type

## Payload Set

- Identifies which payload position receives which wordlist
    

## Attack Types

### Sniper

- Single payload position
    
- Tests one payload at a time
    

### Cluster Bomb

- Multiple payload positions
    
- Tries combinations of payloads
    

# Payload Types

## Simple List

- Most basic payload type
    
- Uses custom wordlist line-by-line
    

## Runtime File

- Loads payloads during attack
    
- Better for huge wordlists
    
- Reduces memory usage
    

## Character Substitution

- Generates permutations automatically
    
- Useful for bypass testing
    

# Payload Configuration

## Loading Wordlists

- Click:
    
    - `Load`
        
- Example wordlist:
    

```text
/opt/useful/seclists/Discovery/Web-Content/common.txt
```

## Manual Entries

- Can add custom payloads manually
    
- Useful for combining multiple wordlists
    

# Payload Processing

## Purpose

- Modify or filter payloads before use
    

# Example Rule

## Skip Hidden Entries

- Ignore lines starting with:
    

```text
.
```

## Regex Used

```regex
^\..*$
```

## Rule Type

```text
Skip if matches regex
```

# Benefits of Payload Processing

- Cleaner scans
    
- Reduced unnecessary requests
    
- Customized fuzzing behavior
    

# Payload Encoding

## Purpose

- Automatically URL-encodes payloads
    

## Why Important

- Prevents malformed requests
    
- Safely handles special characters
    

## Default Behavior

- Usually left enabled
    

# Settings Tab

## Purpose

- Configure attack behavior and response analysis
    

# Retry Options

## Recommended Settings

```text
Retries on network failure = 0
```

```text
Pause before retry = 0
```

# Grep - Match

## Purpose

- Highlights responses matching specific text
    

# Example

## Match Successful Responses

```text
200 OK
```

## Important Option

- Disable:
    

```text
Exclude HTTP headers
```

## Result

- Requests with successful HTTP status become highlighted
    

# Grep - Extract

## Purpose

- Extract specific content from long responses
    
- Useful when only certain response sections matter
    

# Resource Pool

## Purpose

- Controls network resource usage
    
- Useful for large attacks
    

## Default

- Usually left unchanged

# Practical Uses of Intruder

## Directory Enumeration

- Find hidden paths
    

## Password Brute-Forcing

- Test login credentials
    

## Parameter Fuzzing

- Discover hidden parameters
    

## Authentication Testing

- Test weak authentication mechanisms
    

## Active Directory Password Spraying

- Test AD-integrated web applications such as:
    
    - OWA
        
    - SSL VPNs
        
    - Citrix
        
    - RDS portals
        

# Key Takeaways

- Burp Intruder is a powerful built-in web fuzzer
    
- Payload positions define where fuzzing occurs
    
- Wordlists drive the fuzzing process
    
- Payload processing customizes attacks
    
- Grep features help identify useful responses quickly
    
- Burp Community edition is heavily rate-limited
    
- Intruder supports fuzzing, brute-forcing, enumeration, and authentication testing
