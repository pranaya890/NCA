## Purpose of Proxying Tools

- Web proxies can intercept traffic from:
    
    - Command-line tools
        
    - Scripts
        
    - Thick client applications
        
    - Exploitation frameworks
        
- Allows visibility into:
    
    - Requests being sent
        
    - Responses being received
        
- Enables use of proxy features such as:
    
    - Interception
        
    - Modification
        
    - Repeating requests
        
    - Encoding/decoding
        
    - Request analysis
        

## Why Proxy External Tools

- Helps investigate how tools communicate with web servers
    
- Useful for:
    
    - Debugging exploits
        
    - Analyzing scanners
        
    - Modifying automated requests
        
    - Understanding application behavior
        

## Important Note

- Proxying tools can slow them down
    
- Best used only when analyzing or debugging traffic
    

# Proxy Configuration

## Basic Proxy Address

- Most tools use:
    

```text
http://127.0.0.1:8080
```

## Explanation

- `127.0.0.1`
    
    - Localhost address
        
- `8080`
    
    - Default listening port for Burp and ZAP
        

# Proxychains

## What is Proxychains

- Linux tool that routes command-line traffic through a proxy
    
- Works with many CLI applications automatically
    
- Simplifies proxying without modifying tool configurations individually
    

# Configuring Proxychains

## Configuration File

```bash
/etc/proxychains.conf
```

## Original Line

```text
#socks4 127.0.0.1 9050
```

## Add HTTP Proxy

```text
http 127.0.0.1 8080
```

# Quiet Mode

## Using -q

```bash
proxychains -q
```

## Purpose

- Suppresses proxychains connection messages
    
- Keeps terminal output cleaner
    
- Makes tool output easier to read
    

# Example with cURL

## Command

```bash
proxychains -q curl http://SERVER_IP:PORT
```

## Result

- cURL traffic routes through:
    
    - Burp Suite
        
    - Or OWASP Zed Attack Proxy
        
- Request becomes visible in proxy history

# Proxying Metasploit

## Purpose

- Analyze traffic generated by Metasploit modules
    
- Debug exploits and scanners
    
- Modify requests during exploitation
    

# Starting Metasploit

## Launch Command

```bash
msfconsole
```

# Example Module

## Using robots_txt Scanner

```bash
use auxiliary/scanner/http/robots_txt
```

# Setting Proxy in Metasploit

## Proxy Configuration

```bash
set PROXIES HTTP:127.0.0.1:8080
```

## Explanation

- Routes Metasploit HTTP traffic through web proxy
    
![[Pasted image 20260525204442.png]]

# Setting Target Information

## Target Host

```bash
set RHOST SERVER_IP
```

## Target Port

```bash
set RPORT PORT
```

# Running the Module

## Execute Scanner

```bash
run
```

# Result

- Metasploit requests appear in proxy history
    
- Requests can now be:
    
    - Intercepted
        
    - Modified
        
    - Repeated
        
    - Analyzed

# Thick Client Applications

## What Are Thick Clients

- Applications with local processing logic
    
- Often communicate with remote APIs or web servers
    
- Examples:
    
    - Desktop applications
        
    - Electron apps
        
    - Enterprise software
        

## Why Proxy Them

- Inspect hidden API requests
    
- Analyze authentication flows
    
- Discover hidden endpoints
    
- Test request manipulation
    

# Importance in Web Pentesting

- Many tools generate hidden HTTP requests automatically
    
- Proxying exposes the underlying communication
    
- Allows deeper visibility into application behavior
    
- Essential for advanced web application testing
    

# Key Takeaways

- Web proxies can intercept traffic from external tools and applications
    
- Proxychains simplifies proxying command-line tools
    
- Metasploit supports proxy configuration using:
    

```text
set PROXIES
```

- Proxying tools helps analyze, debug, and modify automated requests
    
- Burp and ZAP can intercept traffic from almost any HTTP-enabled tool
    
- Proxying is extremely useful during web application penetration testing
