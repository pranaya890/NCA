## Purpose of Request Repeating

* Request repeating allows resending previously captured HTTP requests without intercepting them again
* Makes repetitive testing much faster during web penetration testing
* Useful when:

  * Testing multiple payloads
  * Enumerating systems
  * Modifying parameters repeatedly
  * Testing vulnerabilities efficiently

## Why It Matters

* Without request repeating, each test would require:

  * Intercepting request
  * Editing payload
  * Forwarding request
  * Checking browser response
  * Repeating process again
* Repeater tools simplify this into:

  * Modify request
  * Click send
  * View response instantly

# Proxy History

## HTTP History in Burp

* In Burp Suite navigate to:

  * `Proxy > HTTP History`
* Displays all captured HTTP requests and responses

## HTTP History in ZAP

* In OWASP Zed Attack Proxy:

  * Bottom `History` tab
  * Or HUD History pane

## Information Shown in History

* Request method
* URL
* Status code
* MIME type
* Response length
* IP address
* Timestamp

## Filtering and Sorting

* Both tools support:

  * Filtering requests
  * Sorting results
  * Searching history
* Useful when handling large amounts of traffic

# WebSockets History

## What It Tracks

* Records WebSocket communications after page load
* Includes:

  * Live updates
  * Asynchronous requests
  * Real-time application data

## Importance

* Useful in advanced web penetration testing
* Helps analyze dynamic web applications

# Viewing Request Details

## Selecting a Request

* Clicking any request displays:

  * Full HTTP request
  * Corresponding server response

## Burp Advantage

* Burp can display:

  * Original Request
  * Edited Request
* Useful for comparing modifications

## ZAP Behavior

* ZAP shows the final modified request only

# Repeating Requests in Burp

## Sending Request to Repeater

* Select request from HTTP History
* Press:

```text id="y8w2fp"
CTRL + R
```

* Opens request in Repeater tab

## Opening Repeater Directly

* Press:

```text id="g5v1zc"
CTRL + SHIFT + R
```

## Sending Modified Requests

* Edit request freely
* Click:

  * `Send`
* Response appears immediately in the response panel

# Burp Repeater Features

## Editable Requests

* Modify:

  * Parameters
  * Headers
  * Cookies
  * Request body
  * HTTP methods

## Changing HTTP Method

* Right-click request
* Select:

  * `Change Request Method`
* Quickly switch:

  * GET ↔ POST

# Repeating Requests in ZAP

## Request Editor

* Right-click request from history
* Select:

  * `Open/Resend with Request Editor`

## Features

* Editable request panel
* Send button for replaying requests
* Response displayed instantly

## HTTP Method Dropdown

* Easily switch request methods
* Supports multiple HTTP verbs

# ZAP HUD Replay

## Replaying Requests from HUD

* Select request from HUD History pane
* Request Editor appears inside browser

## Replay Options

### Replay in Console

* Shows response inside HUD console

### Replay in Browser

* Renders response directly in browser

# Modifying Requests

## Editable Content

* All repeater tools allow changing:

  * Parameters
  * Payloads
  * Headers
  * Methods
  * Cookies

## Example

Original request:

```http id="r2m8xh"
ip=1
```

Modified request:

```http id="v7k5nd"
ip=;ls;
```

## Result

* Server executes modified command
* Response instantly displayed in repeater tool

# URL Encoding

## Important Observation

* POST data often appears URL-encoded

Example:

```text id="p4j9tw"
%3Bls%3B
```

## Why URL Encoding Matters

* Special characters are encoded for safe HTTP transmission
* Important when crafting custom requests manually
* Frequently encountered in:

  * Form submissions
  * Query parameters
  * API requests
