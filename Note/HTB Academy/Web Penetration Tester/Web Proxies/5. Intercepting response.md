## Purpose of Response Interception

- Response interception allows us to capture HTTP responses before they reach the browser
- Helps modify how a web page is rendered
- Useful for:
    - Enabling disabled fields
    - Showing hidden fields
    - Removing front-end restrictions
    - Modifying page behavior during testing
- Makes web application penetration testing easier by bypassing client-side controls
    

# Response Interception in Burp Suite

## Enabling Response Interception

- In Burp Suite navigate to:
    
    - `Proxy > Proxy Settings`
        
- Enable:
    
    - `Intercept responses based on the following rules`
        

## Capturing Responses

- Turn request interception ON
    
- Refresh the page using:
    

```text
CTRL + SHIFT + R
```

- Burp first intercepts the request
    
- Click:
    
    - `Forward`
        
- Burp then intercepts the server response
    

# Modifying HTML Responses

## Original Input Field

```html
<input type="number" id="ip" name="ip" maxlength="3">
```

## Problem

- Browser only allows numeric values
    
- Input length restricted to 3 characters
    
- Front-end validation blocks payload injection
    

## Modified Input Field

```html
<input type="text" id="ip" name="ip" maxlength="100">
```

## Changes Made

- Changed:
    

```html
type="number"
```

to:

```html
type="text"
```

- Changed:
    

```html
maxlength="3"
```

to:

```html
maxlength="100"
```

# Result of Modification

- Browser now accepts any input
    
- Longer payloads can be entered directly into the form
    
- No need to intercept and edit every request manually
    
- Useful for testing payloads directly from the browser
    

# Benefits of Response Manipulation

- Bypass front-end JavaScript restrictions
    
- Enable hidden or disabled functionality
    
- Simplify payload testing
    
- Improve testing workflow efficiency
    

# Response Interception in ZAP

## Capturing Responses

- In OWASP Zed Attack Proxy intercepted requests can be forwarded using:
    
    - `Step`
        
- ZAP automatically intercepts the corresponding response
    

## Modifying Responses

- Edit HTML response content directly
    
- Apply same modifications:
    
    - Change input type
        
    - Increase maxlength
        
- Click:
    
    - `Continue`
        
- Modified page loads in browser
    

# ZAP HUD Features

## Show/Enable Fields Feature

- HUD provides a quick way to:
    
    - Enable disabled fields
        
    - Show hidden fields
        
- No manual response interception required
    

## Light Bulb Icon

- Third button on left-side HUD menu
    
- Automatically enables hidden or disabled inputs
    

# Example Use Case

## Disabled Input Field

- Application disables the IP input field in HTML
    

## Using HUD

- Click:
    
    - `Show/Enable`
        
- Field becomes interactive immediately
    
- Allows entering custom payloads directly
    

# Hidden Fields and Buttons

- HUD can reveal:
    
    - Hidden input fields
        
    - Hidden buttons
        
    - Hidden form elements
        
- Useful for discovering hidden application functionality
    

# Similar Burp Feature

## Burp Response Modification Rules

Navigate to:

- `Proxy > Proxy Settings > Response Modification Rules`
    

## Available Options

- Unhide hidden form fields
    
- Remove disabled attributes
    
- Automatically modify responses
    

# HTML Comments Discovery

## ZAP Comments Feature

- HUD can display hidden HTML comments directly on the page
    
- Comments may contain:
    
    - Developer notes
        
    - Debugging information
        
    - Hidden endpoints
        
    - Sensitive hints
        

## Enabling Comments Feature

- Click:
    
    - `+`
        
- Select:
    
    - `Comments`
        

## Result

- Comment indicators appear on the page
    
- Hovering reveals hidden comment contents
    

# Why Response Interception Matters

- Allows manipulation of client-side behavior
    
- Helps bypass front-end security controls
    
- Improves visibility into hidden functionality
    
- Makes vulnerability testing faster and easier
    
- Useful for testing applications without constantly modifying requests manually
    

# Key Takeaways

- Response interception modifies server responses before rendering in the browser
    
- Burp and ZAP both support response interception and manipulation
    
- Changing HTML attributes can bypass front-end restrictions
    
- ZAP HUD provides fast enable/show functionality for hidden elements
    
- HTML comments may reveal useful penetration testing information
    
- Response modification greatly improves web application testing efficiency
