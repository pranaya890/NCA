
## Purpose of Request Interception

- Web proxies allow us to capture HTTP/HTTPS requests before they reach the server
- Intercepted requests can be:
    - Examined
    - Modified
    - Forwarded
    - Dropped

- Helps penetration testers understand:
    - How applications communicate with servers
    - What data is being transmitted
    - How the server reacts to manipulated input


# Intercepting Requests in Burp Suite

## Enabling Interception

- In Burp Suite:
    - Navigate to:
        - `Proxy > Intercept`
- Interception is enabled by default
- Button options:
    - `Intercept is on`
    - `Intercept is off`

---

## Capturing Requests

- Open Burp's pre-configured browser
- Visit the target web application
- Burp captures the request before it reaches the server
- Intercepted request appears inside the Proxy tab

---

## Forwarding Requests

- Click:
    - `Forward`
- Sends the intercepted request to the target server

---

## Important Note

- Burp intercepts all browser traffic
- Multiple requests may appear before the target request
- Continue clicking `Forward` until the desired request appears

---

# Intercepting Requests in ZAP

## Enabling Interception

- In OWASP Zed Attack Proxy:
    
    - Interception is OFF by default
        
- Green button indicates requests pass normally
    
- Click the button or use:
    

```text
CTRL+B
```

to toggle interception

---

## Capturing Requests

- Launch ZAP's pre-configured browser
    
- Visit or refresh the target page
    
- Intercepted request appears in the top-right pane
    

---

## Forwarding Requests

- Click:
    
    - `Step`
        
- Sends the request while continuing interception for upcoming requests
    

---

# ZAP Heads Up Display (HUD)

## What is HUD

- HUD allows controlling ZAP features directly inside the browser
    
- Provides easier interaction without switching between browser and ZAP interface
    

---

## Enabling HUD

- Click HUD button on the top toolbar
    
- HUD interface appears inside the browser window
    

---

## HUD Request Interception

- Use interception button from left-side HUD menu
    
- Intercepted requests appear directly in the browser
    

---

## HUD Controls

- `Step`
    
    - Forward current request and continue intercepting future requests
        
- `Continue`
    
    - Forward current and remaining requests without stopping
        
- `Drop`
    
    - Discard the intercepted request completely
        

---

## Step vs Continue

- `Step`
    
    - Useful for analyzing every stage of application behavior
        
- `Continue`
    
    - Useful when only interested in a specific request
        

---

# Manipulating Intercepted Requests

## Why Manipulate Requests

- Front-end applications often restrict user input using JavaScript
    
- Intercepting requests allows bypassing front-end restrictions
    
- Helps test whether the back-end properly validates user input
    

---

## What Can Be Modified

- Parameters
    
- Headers
    
- Cookies
    
- Authentication tokens
    
- HTTP methods
    
- Request body content
    

---

# Example HTTP Request

```http
POST /ping HTTP/1.1
Host: 94.237.62.138:32306
Content-Type: application/x-www-form-urlencoded

ip=1
```

---

# Understanding the Example

- User enters an IP address in a web form
    
- Front-end JavaScript only allows numeric input
    
- Browser normally prevents special characters
    

---

# Bypassing Front-End Restrictions

- Using interception, we can modify:
    

```text
ip=1
```

to:

```text
ip=;ls;
```

---

# Result of Manipulation

- Modified request gets forwarded to the server
    
- Application executes:
    

```bash
ls
```

- Response displays server files such as:
    
    - flag.txt
        
    - index.html
        
    - node_modules
        
    - server.js
        

---

# What This Demonstrates

- Back-end failed to properly validate user input
    
- Command injection vulnerability exists
    
- Front-end validation alone is not secure
    
- Attackers can bypass client-side restrictions using web proxies
    

---

# Common Vulnerabilities Tested with Request Manipulation

## SQL Injection

- Inject malicious SQL queries into parameters
    
- Used to access or manipulate databases
    

---

## Command Injection

- Execute operating system commands on the server
    

---

## Upload Bypass

- Bypass file upload restrictions
    
- Upload malicious files or scripts
    

---

## Authentication Bypass

- Manipulate authentication requests
    
- Attempt unauthorized access
    

---

## Cross-Site Scripting (XSS)

- Inject JavaScript into web applications
    
- Execute scripts in victim browsers
    

---

## XML External Entity (XXE)

- Exploit insecure XML parsers
    
- Read local files or interact with internal systems
    

---

## Error Handling Testing

- Trigger unexpected application behavior
    
- Identify sensitive error disclosures
    

---

## Deserialization Attacks

- Manipulate serialized objects
    
- Potentially achieve remote code execution
    

---

# Importance of Request Manipulation

- Core skill in web application penetration testing
    
- Allows deeper analysis than normal browser interaction
    
- Essential for discovering hidden vulnerabilities
    
- Helps test how secure the back-end validation really is
    

---

# Key Takeaways

- Interception allows capturing requests before they reach the server
    
- Burp and ZAP both support request interception and modification
    
- Manipulating requests bypasses client-side restrictions
    
- Web proxies help identify vulnerabilities caused by poor back-end validation
    
- Request interception is fundamental for advanced web application testing
