# Web Applications vs Native OS Applications

## Web Applications
- Platform-independent
  - Can run in a browser on any operating system.
- No installation required
  - Executed remotely on a server.
  - Do not consume storage space on the user’s hard drive.
- Version unity
  - All users access the same version of the application.
  - Updates and modifications happen centrally on the webserver.
- Easier maintenance
  - No need to create separate builds for different platforms.
  - Reduces maintenance and support costs.
  - No need to individually push updates to users.

## Native Operating System (OS) Applications
- Faster performance
  - Built using native OS libraries.
  - Faster loading and interaction speed.
- Better hardware and OS integration
  - Can directly utilize local hardware and operating system resources.
  - More capable than browser-limited web applications.
- Requires installation
  - Installed locally on the user’s device.
  - Consumes local storage space.

## Hybrid & Progressive Web Applications (PWAs)
- Becoming increasingly common.
- Use modern frameworks to combine:
  - Web application flexibility
  - Native OS capabilities and resources
- Advantages
  - Faster than traditional web applications.
  - More capable due to access to native features and hardware resources.

### Security Risk of Web Applications

#### General Risks
- Web application attacks are very common.
- Organizations of all sizes with a web presence are targets.
- Web applications are:
  - Accessible globally through the internet.
  - Available to anyone with a browser and internet connection.
  - Usually have a large attack surface.
- Automated tools exist for:
  - Scanning web applications
  - Attacking vulnerabilities
- Increasing application complexity increases the possibility of critical vulnerabilities.

#### Impact of Successful Attacks
- Can cause:
  - Significant financial losses
  - Major business interruptions
- Web applications often:
  - Run on servers containing sensitive information.
  - Connect to databases with user or corporate data.
- A successful attack may compromise:
  - Sensitive data
  - Corporate data
  - User information

#### Importance of Security Testing
- Organizations must:
  - Test web applications for vulnerabilities regularly.
  - Patch vulnerabilities promptly.
  - Verify patches properly fix flaws.
  - Ensure patches do not introduce new vulnerabilities.

#### Web Application Penetration Testing
- Increasingly important cybersecurity skill.
- Organizations should:
  - Frequently test internet-facing and internal web applications.
  - Implement secure coding practices during all SDLC stages.
- Pentesters must understand:
  - How web applications work
  - How they are developed
  - Risks in each layer and component
  - Technologies used by the application

#### Web Application Diversity
- Web applications differ in:
  - Design
  - Configuration
  - Technologies used

#### OWASP Web Security Testing Guide
- One of the most widely used methodologies for web application testing.
  https://github.com/OWASP/wstg/blob/master/document/4-Web_Application_Security_Testing/00-Introduction_and_Objectives/README.md

#### Common Web Application Testing Procedure

##### 1. Front End Testing
- Review front end components:
  - HTML
  - CSS
  - JavaScript
- Known as the "Front End Trinity".
- Look for vulnerabilities such as:
  - Sensitive Data Exposure --> Resource: https://owasp.org/www-project-top-ten/2017/A3_2017-Sensitive_Data_Exposure
  - Cross-Site Scripting (XSS) --> Resource:  https://owasp.org/www-project-top-ten/2017/A7_2017-Cross-Site_Scripting_(XSS)

##### 2. Core Functionality Testing
- Analyze interaction between:
  - Browser
  - Webserver
- Enumerate technologies used by the webserver.
- Search for exploitable vulnerabilities.

##### 3. Authentication Perspective Testing
- Test applications from:
  - Unauthenticated perspective
  - Authenticated perspective (if login exists)
- Purpose:
  - Maximize testing coverage
  - Identify all possible attack scenarios

### Web Application Vulnerabilities & Security Risks

#### Web Applications in Modern Organizations
- Almost every company has one or more web applications exposed externally.
- Types of web applications include:
  - Static websites
  - Blogs
  - CMS-based applications (e.g., WordPress)
  - Complex applications with:
    - Sign-up/login functionality
    - Multiple user roles
      - Basic users
      - Administrators
      - Super admins

#### Attack Surface of Web Applications
- Modern external hosts are less commonly vulnerable to direct public exploits.
- Web applications provide a large attack surface because they:
  - Are dynamic
  - Constantly change
  - Are often overlooked
- Small code changes may introduce:
  - Critical vulnerabilities
  - Multiple vulnerabilities that can be chained together

#### Potential Impact of Vulnerabilities
- Attackers may gain:
  - Access to sensitive data
  - Remote Code Execution (RCE)
  - Access to database servers
  - Access to other internal systems

#### Common Vulnerabilities

##### File Upload Vulnerabilities
- Malicious files may be uploaded through insecure upload forms.
- Can lead directly to remote code execution.

##### File Inclusion Vulnerabilities
- Allow attackers to include malicious or unintended files.
- May result in remote code execution.

##### SQL Injection (SQLi)
- One of the most common web vulnerabilities.
- Caused by unsafe handling of user input.
- Can lead to:
  - Access to sensitive data
  - Reading files from database servers
  - Writing files to database servers
  - Remote code execution

#### SQL Injection & Active Directory
- SQL injection is often found in applications using Active Directory authentication.
- Passwords usually cannot be extracted directly because AD manages them.
- Attackers may still retrieve:
  - User email addresses
  - Usernames

##### Password Spraying Attacks
- Extracted usernames/emails can be used for password spraying.
- Common targets:
  - VPN portals
  - Microsoft Outlook Web Access (OWA)
  - Microsoft O365
- Successful password spraying may provide:
  - Access to sensitive emails
  - Foothold into the corporate network
    https://www.cisa.gov/news-events/alerts/2019/08/08/acsc-releases-advisory-password-spraying-attacks

##### Vulnerability Chaining
- A single vulnerability can be chained with others to escalate attacks.
- Example:
  1. SQL injection extracts usernames/emails.
  2. Password spraying gains account access.
  3. Access leads to compromise of internal infrastructure.

### Importance for Security Professionals
- Infosec professionals should understand:
  - Web applications
  - Web attacks
  - Network penetration testing
  - Active Directory attacks
- Strong web application knowledge helps penetration testers:
  - Discover overlooked vulnerabilities
  - Stand out from peers
