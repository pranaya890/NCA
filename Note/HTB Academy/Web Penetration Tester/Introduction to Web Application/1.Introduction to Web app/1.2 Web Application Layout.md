### Client Sever
- server host web application in a client server model and distributes it to any client accessing it
![[Pasted image 20260515211945.png]]

- Web applications contain two main component types:
  - Front end components
    - Executed/interpreted on the client side (browser).
    - Responsible for the user interface and user interaction.
  - Back end components
    - Executed on the hosting server.
    - Responsible for processing requests and application logic.

- When a user visits a web application's URL (e.g., `https://www.acme.local`):
  - The server sends the web application's interface (UI) to the browser.
  - The user interacts with the application by:
    - Clicking buttons
    - Logging in
    - Browsing pages
    - Adding items to a cart
  - The browser sends an HTTP request to the server.
  - The server interprets the request and performs the required task.
  - The server sends the response/data back to the browser.
  - The browser displays the result in a human-readable format.

- Example:
  - Hack The Box platform follows the client-server model.
  - The application is hosted on a webserver.
  - Users access and interact with it through a web browser (client).

- Most web applications use:
  - Client-server architecture
  - Front end/back end architecture
- Many implementation and design variations of this architecture exist.

### One Server
- Entire web application architecture is hosted on a single server.
- Components hosted on the same server may include:
  - Web applications
  - Front end components
  - Back end components
  - Databases
- Multiple web applications may also be hosted on the same server.
- Advantages:
  - Simple architecture
  - Easy to implement
- Disadvantages/Risks:
  - Considered the riskiest architecture design.
  - Follows an "all eggs in one basket" approach.
  - If one hosted web application is compromised:
    - All applications and their data may be compromised.
    - Entire webserver becomes vulnerable.
  - If the server goes down:
    - All hosted web applications become inaccessible until resolved.

### Many Server- One database

- Database is separated onto its own dedicated database server.
- Web application servers communicate with the database server to:
  - Store data
  - Retrieve data
- Can function as:
  - Many servers → one database
  - One server → one database
- Main concept:
  - Database is hosted separately from web application servers.
- Multiple web applications can access the same database.
- Benefits:
  - Shared access to common data
  - No need to sync data between applications

- Web applications may be:
  - Replicas of the same application
    - Primary/backup systems
  - Different applications sharing common data

- Main security advantage:
  - Segmentation
  - Major components are hosted separately.

- Security benefits of segmentation:
  - If one webserver is compromised:
    - Other webservers are not directly affected.
  - If the database is compromised (e.g., via SQL injection):
    - Web applications are not directly compromised.

- Additional security measures are still required:
  - Implement proper access controls.
  - Restrict applications to only the data required for functionality.

### Many Server -Many Database
- Extension of the "Many Servers - One Database" model.
- Each web application has its own separate database.
- Databases may:
  - Exist on the same database server
  - Be hosted on separate database servers

- Web applications can access:
  - Their own private data
  - Shared/common data when permitted

- Main advantages:
  - Stronger asset segmentation
  - Improved access control
  - Better security isolation

- Widely used for:
  - Redundancy
  - High availability
  - Reduced downtime

- If a webserver or database fails:
  - Backup systems can replace it.

- Additional infrastructure/components may be required:
  - Load balancers
  - Backup systems
  - Redundancy mechanisms

- Security benefits:
  - One of the most secure architectures.
  - Proper separation between applications and databases.
  - Limits impact of compromises through segmentation and access controls.

- Disadvantages:
  - More complex to implement
  - Requires additional infrastructure and configuration

# Microservices Architecture

- Microservices are independent components of a web application.
- Each microservice is usually designed for a single specific task.
- Example components in an online store:
  - Registration
  - Search
  - Payments
  - Ratings
  - Reviews
- Microservices communicate:
  - With the client
  - With other microservices
- Communication between microservices is:
  - Stateless
  - Each request/response is independent
- Application data is stored separately from the microservices themselves.
- Microservices architecture is considered:
  - Service-Oriented Architecture (SOA) : https://en.wikipedia.org/wiki/Service-oriented_architecture
  - Collection of automated services focused on specific business goals
- Although independent, microservices still depend on each other.
- Important feature:
  - Different microservices can be written in different programming languages while still interacting together.
- Advantages of microservices:
  - Easier scaling
  - Faster application development
  - Encourages innovation
  - Faster delivery of new features
- Benefits:
  - Agility
  - Flexible scaling
  - Easy deployment
  - Reusable code
  - Resilience
  Overview reference: https://d1.awsstatic.com/whitepapers/microservices-on-aws.pdf

### Web Applications

- web applications are interactive applications that run on web browsers
- usually use client-server architecture to process and handle instructions
- typically contain:
  - frontend components
    - what users see and interact with
  - backend components
    - web application source code running on the server
- allow organizations to host powerful applications with:
  - real-time control over functionality
  - real-time control over design
  - worldwide accessibility through the internet
- examples:
  - online email systems like `Gmail`
  - online retailers like `Amazon`
- web applications are not limited to large companies like Google
- any web developer can create and host web applications using common hosting services
- applications can be made accessible to anyone on the internet

# Architecture Security

- understanding both general web application architecture and the application's specific design is important during penetration testing
- vulnerabilities may be caused by:
  - programming errors
  - architectural/design flaws
- applications may implement functionality securely but still remain vulnerable due to poor security design
- lack of proper access control measures such as [Role-Based Access Control (RBAC)](https://en.wikipedia.org/wiki/Role-based_access_control) may allow:
  - unauthorized access to admin functionality
  - access to other users' private information
  - privilege escalation
- fixing architectural vulnerabilities usually requires:
  - major design changes
  - higher cost
  - more development time
- after compromising a backend server:
  - inability to locate the database may indicate it is hosted on a separate server
  - access to partial database data may indicate multiple databases are being used
- security should be considered during every phase of web application development
- penetration testing should be performed continuously throughout the Software Development Life Cycle (SDLC)
