### Front End

- front end contains components directly accessible and executed on the client-side through the web browser
- front end source code usually consists of:
  - `HTML`
  - `CSS`
  - `JavaScript`
- browser interprets and renders these technologies in real time

- front end controls everything users see and interact with, including:
  - page structure and text (`HTML`)
  - styling, layout, colors, and animations (`CSS`)
  - page functionality and interactivity (`JavaScript`)

- modern front end applications should:
  - adapt to different screen sizes
  - work across multiple browsers
  - support multiple devices including mobile devices

- unlike front end components, backend components are usually developed for specific platforms or operating systems

- poorly optimized front end code can cause:
  - slow web applications
  - unresponsive user interfaces
  - poor user experience
- users may mistakenly think:
  - the server is slow
  - their internet connection is slow
  when the issue actually exists on the client side

- front end optimization is important for:
  - performance
  - responsiveness
  - compatibility across platforms and devices

- tasks related to front end development include:
  - visual concept web design
  - User Interface (`UI`) design
  - User Experience (`UX`) design

### Backend
- back end drives the core functionality of a web application
- all backend processing is executed on the server side
- without a backend, a website is only a collection of static web pages
- users usually do not directly see or interact with backend components

- four main backend components:

| Component | Description |
|---|---|
| Back end Servers | Hardware and operating systems hosting application components; commonly Linux, Windows, or Containers |
| Web Servers | Handle HTTP requests and client connections; examples: `Apache`, `NGINX`, `IIS` |
| Databases | Store and retrieve application data |
| Development Frameworks | Used to develop the core functionality of web applications |

- examples of databases:
  - relational databases:
    - `MySQL`
    - `MSSQL`
    - `Oracle`
    - `PostgreSQL`
  - non-relational databases:
    - `NoSQL`
    - `MongoDB`

- examples of development frameworks:
  - `Laravel` (`PHP`)
  - `ASP.NET` (`C#`)
  - `Spring` (`Java`)
  - `Django` (`Python`)
  - `Express` (`NodeJS/JavaScript`)

- backend components may be:
  - hosted on the same server
  - hosted on isolated servers
  - hosted in isolated containers
  
![[Pasted image 20260517210007.png]]

- containerization technologies such as `Docker` can isolate application components

- example:
  - database hosted in one container
  - web application hosted in another container

- benefits of isolation:
  - logical separation
  - reduced impact of vulnerabilities
  - better security segmentation

- hosting each component on separate servers provides:
  - stronger isolation
  - better segmentation
- disadvantages:
  - higher resource usage
  - increased maintenance complexity

- backend design depends on:
  - business requirements
  - application design
  - application functionality


Some of the main jobs performed by back end components include:

- Develop the main logic and services of the back end of the web application
- Develop the main code and functionalities of the web application
- Develop and maintain the back end database
- Develop and implement libraries to be used by the web application
- Implement technical/business needs for the web application
- Implement the main APIs for front end component communications
- Integrate remote servers and cloud services into the web application

###  Securing Front/Back End

- lack of access to backend source code does not make a web application secure or invulnerable
- backend vulnerabilities may still be exploited through:
  - injection attacks
  - insecure input handling

- example:
  - improperly processed search functionality may allow attackers to manipulate queries
  - this can lead to:
    - `SQL Injection`
      - unauthorized access to database data
    - `Command Injection`
      - execution of operating system commands through the web application

- when frontend source code is fully accessible:
  - code reviews can be performed
  - vulnerabilities can be identified directly from the source code
- this type of testing is known as:
  - `Whitebox Pentesting`

- backend source code is usually stored on the backend server
- by default:
  - testers do not have access to backend source code
- this type of testing is known as:
  - `Blackbox Pentesting`

- some web applications are open source:
  - source code may be publicly accessible

- certain vulnerabilities may expose backend source code
- example:
  - `Local File Inclusion (LFI)`

- obtaining backend source code allows:
  - code review of backend components
  - better understanding of application functionality
  - discovery of sensitive information
    - passwords
    - credentials
    - configuration data
  - identification of vulnerabilities difficult to discover through blackbox testing alone
