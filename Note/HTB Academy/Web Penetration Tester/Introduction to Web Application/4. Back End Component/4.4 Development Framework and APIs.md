

- web development frameworks help developers:
  - build web applications faster
  - simplify development
  - implement common functionality easily

- modern web applications are complex
- building applications completely from scratch can be difficult and time-consuming

- frameworks provide:
  - reusable components
  - built-in functionality
  - easier frontend/backend integration

- common shared web application functionality includes:
  - user registration
  - authentication
  - session management
  - routing
  - database interaction

- frameworks help connect:
  - frontend components
  - backend logic

# Common Development Frameworks
- [Laravel](https://laravel.com/) (`PHP`): usually used by startups and smaller companies, as it is powerful yet easy to develop for.
- [Express](https://expressjs.com/) (`Node.JS`): used by `PayPal`, `Yahoo`, `Uber`, `IBM`, and `MySpace`.
- [Django](https://www.djangoproject.com/) (`Python`): used by `Google`, `YouTube`, `Instagram`, `Mozilla`, and `Pinterest`.
- [Rails](https://rubyonrails.org/) (`Ruby`): used by `GitHub`, `Hulu`, `Twitch`, `Airbnb`, and even `Twitter` in the past.

- large/popular websites often use:
  - multiple frameworks
  - multiple web servers
  - combined technologies instead of a single platform
# APIs

- APIs (`Application Programming Interfaces`) are used to connect:
  - frontend components
  - backend components

- APIs allow:
  - sending data between frontend and backend
  - requesting backend functionality
  - processing user actions

- frontend components use APIs to:
  - send requests
  - provide input values
  - request specific actions from the backend

- backend components:
  - process requests
  - perform required functions
  - return responses to the frontend

- frontend then:
  - renders output to the user
  - displays processed results in the browser

# Query Parameters

- web applications commonly pass data using:
  - `GET` parameters
  - `POST` parameters

- query parameters allow:
  - sending user input to backend pages/functions
  - dynamic processing of requests

- example GET request:
```http
/search.php?item=apples
````

- example POST request:
    

```http
POST /search.php HTTP/1.1

item=apples
```

- example:
    
    - `/search.php` receives the parameter:
        
        - `item`
            
    - backend processes the value:
        
        - `apples`
            
- query parameters enable:
    
    - one page to process multiple inputs
        
    - dynamic functionality
        
    - flexible backend processing
        
- APIs are often:
    
    - faster
        
    - more efficient  
        than traditional parameter handling for certain use cases

# Web APIs

- `API` stands for:
  - `Application Programming Interface`

- APIs define:
  - how applications interact with other applications

- in web applications, APIs allow:
  - remote access to backend functionality
  - communication between frontend and backend systems

- APIs are not limited to web applications
- used widely in:
  - software applications
  - services
  - system integrations

- Web APIs usually:
  - operate over `HTTP`
  - are handled through web servers

# How Web APIs Work

- clients send requests to API endpoints
- backend processes the request
- API returns data or performs actions

- responses are commonly returned in:
  - `JSON`
  - `XML`

# Examples

- weather application API:
  - receives:
    - city name
    - city ID
  - returns:
    - weather data in JSON format

- `Twitter API` can:
  - retrieve tweets
  - return XML/JSON data
  - send tweets if authenticated

# API Standards

- developers implement APIs on backend systems using standards such as:
  - `SOAP`
  - `REST`

# SOAP

- `SOAP` stands for:
  - `Simple Object Access Protocol`

- SOAP transfers data using:
  - `XML`

- SOAP requests:
  - are sent through HTTP requests
  - contain XML-formatted data

- SOAP responses:
  - are also returned in XML format

- frontend applications must:
  - parse XML responses properly

# Example SOAP Message

```xml
<?xml version="1.0"?>

<soap:Envelope
xmlns:soap="http://www.example.com/soap/soap/"
soap:encodingStyle="http://www.w3.org/soap/soap-encoding">

<soap:Header>
</soap:Header>

<soap:Body>
  <soap:Fault>
  </soap:Fault>
</soap:Body>

</soap:Envelope>
````

# Features

- SOAP is useful for:
    
    - transferring structured data
        
    - sharing serialized objects
        
    - transferring binary data
        
- supports:
    
    - complex object communication
        
    - stateful data exchange
        
- commonly used for:
    
    - modern web applications
        
    - mobile applications
        
    - applications requiring structured communication
        
- SOAP can manage:
    
    - current application state
        
    - page state changes
        
    - object synchronization
        

# Limitations

- SOAP can be:
    
    - difficult for beginners
        
    - verbose
        
    - complex for simple operations
        
- even simple queries may require:
    
    - large XML requests
        
    - complicated request structures
        
- for lightweight/simple API operations:
    
    - `REST APIs` are often preferred

# REST

- `REST` stands for:
  - `Representational State Transfer`

- REST APIs exchange data through:
  - URL paths
- example:
```http
/search/users/1
````

- REST APIs usually return data in:
    
    - `JSON` format
        

# Characteristics

- unlike query parameters:
    
    - REST APIs pass data directly through URL paths
        
    - input names/types are often implied by endpoint structure
        
- REST APIs are commonly used for:
    
    - searching
        
    - sorting
        
    - filtering
        
    - modular application functionality
        
- REST architecture breaks applications into:
    
    - smaller APIs
        
    - modular services
        
- benefits:
    
    - scalability
        
    - modularity
        
    - easier maintenance
        
    - flexible frontend/backend communication
        

# REST Responses

- responses are commonly returned as:
    
    - `JSON`
        
- other supported formats:
    
    - `XML`
        
    - `x-www-form-urlencoded`
        
    - raw data
        
- frontend components process API responses and render data to users
    

# Example JSON Response

```json
{
  "100001": {
    "date": "01-01-2021",
    "content": "Welcome to this web application."
  },
  "100002": {

  },
  "100003": {
    "date": "02-01-2021",
    "content": "Reminder: Tomorrow is the ..."
  }
}
```

# HTTP Methods Used in REST APIs

|Method|Purpose|
|---|---|
|`GET`|Retrieve data|
|`POST`|Create data (`non-idempotent`)|
|`PUT`|Create or replace data (`idempotent`)|
|`DELETE`|Remove data|

# Notes

- `POST`
    
    - may create duplicate actions if repeated
        
    - non-idempotent
        
- `PUT`
    
    - repeated requests produce the same result
        
    - idempotent
