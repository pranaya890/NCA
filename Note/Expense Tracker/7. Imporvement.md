# One Last Recommendation Before We Code

Since you're learning Docker, Django, PostgreSQL, MongoDB, and software architecture all at once, I'd like to introduce one more rule for the project:

> **No business logic in models.**

We'll organize the backend like this:

```
views.py
    │
    ▼
serializers.py
    │
    ▼
services.py   ← ALL business logic
    │
    ▼
repositories/selectors.py
    │
    ▼
models.py
```

That means:

* `models.py` only defines the data structure.
* `serializers.py` validates input.
* `services.py` handles financial operations (e.g., creating an expense, recalculating balances, running verification).
* `selectors.py` or repositories encapsulate read queries.

This separation is more advanced than the default Django approach, but it's widely used in larger Django projects because it keeps business logic centralized and testable.
